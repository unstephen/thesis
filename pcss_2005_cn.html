Percentage-Closer Soft Shadows（PCSS）

硬阴影假、均匀软阴影更假——真实半影在接触点收窄（contact hardening）。PCSS 用 blocker search 估计平均遮挡物深度、按相似三角形算半影宽度、再按该宽度做 PCF，第一次把'物理正确感'的软阴影做到实时。如今所有引擎的软阴影（UE 的 Source Radius、Unity 的软阴影）都是它的直系后代。

这是一篇 SIGGRAPH 2005 的 Sketch（短文/海报类发表），正文 1 页、补充材料 3 页，作者 Randima（Randi）Fernando 时任职于 NVIDIA，也是 GPU Gems 系列的主编之一。篇幅极短，却是此后二十年实时软阴影事实上的源头文献：PCSS 这个名字、三步流水线（blocker search → penumbra estimation → PCF filtering）以及那条半影宽度公式，都出自这 4 页。需要注意 sketch 体例不做完整推导：正文只给结论，唯一的公式出现在第 3 页补充材料的示意图旁，实现细节（搜索半径的投影换算、偏移（bias）的取法、采样分布）要参考 NVIDIA 当年随官方 SDK / FX Composer 发布的 PCSS 示例以及后续论文。对引擎开发者而言，本文的真正价值在于它把"软阴影"从一个几何问题（软阴影体、多重光源采样、多张 shadow map 混合）重写成一个逐像素的纹理滤波问题，因此能原封不动地塞进现有阴影映射（shadow mapping）管线：shadow pass、视锥（frustum）与光空间（light space）矩阵全部不动，只改着色时的深度贴图（depth map）查询。术语对照贯穿全文：blocker / occluder 统一译作遮挡物（blocker），receiver 译作接收体（receiver），penumbra 译作半影，umbra 译作本影。

1. 引言

1. Introduction
🔍 编辑部按

引言把问题定义得非常干净：面光源（area light）下的软阴影。物理图像是——接收体（receiver）上一点能看到的光源立体角越大，阴影越浅、越宽；当遮挡物（blocker）与接收体接触时，该点对光源的可见立体角在掠射方向上趋近于零，于是阴影边缘锐利，这就是"接触硬化"（contact hardening）。作者刻意用 perceptually accurate（感知上准确）而不是 physically correct（物理正确）来定位 PCSS：它追求"看起来对"——半影宽度随遮挡物距离正确变化、接触处锐利——但并不做面光源的严格积分，也不保证能量守恒。这一定位决定了它全部的工程卖点：不改几何 pass、不增加 shadow map 数量、纯 shader 侧替换。对熟悉 DX12/Vulkan 的读者，这等价于"只动像素 shader + 换一个比较采样器（comparison sampler）的用法"，顶点/几何阶段与 shadow map 渲染完全复用。引言还提前回答了审稿人最可能质疑的成本问题：单张 shadow map、无预处理、无后处理、无额外几何体。

英文原文
One of the fundamental problems in computer graphics is generating accurate soft shadows from area light sources. Soft shadows provide valuable cues about the relationships between objects, becoming sharper as objects contact each other and more blurry (softer) the further they are apart. [Page 1 carries an uncaptioned rendering between this paragraph and the next: a teapot, ladle, spatula and other utensils resting on a textured stone surface, showing shadows that are sharp at contact points and increasingly soft with distance.]

计算机图形学的一个根本问题，是从面光源（area light）生成精确的软阴影。软阴影能为物体之间的空间关系提供宝贵线索：物体相互接触时阴影变锐利，彼此相距越远则越模糊（越软）。[第 1 页在本段与下一段之间有一张无图注的渲染图：石质纹理台面上摆放的茶壶、汤勺、锅铲等物件，可见接触处锐利、离接触点越远越软的阴影。]

🔍 专家解析

五条特性里最值得抠字眼的是第二条：Uses a single light source sample (one shadow map)。这里的"单次光源采样"不是"每像素采一个光源样本"，而是"整个面光源只用一张 shadow map 来表示"。它针对的是当年主流的多重采样软阴影方案——把面光源拆成 N 个点光源、渲染 N 张 shadow map 再叠加——那种做法的成本随样本数线性增长，显存也成倍增加。PCSS 只有一张深度贴图（depth map），"软"的观感来自对这张图的滤波，而不是多图混合，所以显存与 shadow pass 成本与传统阴影映射完全相同。第三、四条是工程上的关键：不需要预处理、后处理或额外几何体，意味着它自动继承阴影映射的全部兼容性——alpha test（镂空植被、铁丝网）、displacement mapping、alpha-to-coverage、蒙皮与实例化全都不用改，因为 shadow pass 根本没有变。对比需要挤出几何的软阴影体（soft shadow volumes）或需要多重渲染的方案，这正是它能"无缝替换传统 shadow map 查询"的原因：管线里唯一的变化是着色时对深度贴图的查询方式，也就是把一次 SampleCmp 换成一段几十次采样的循环。还要注意"perceptually accurate"这个限定词：PCSS 的结果不是面光源积分的数值近似，半影内的明暗剖面由 PCF 核的采样分布决定，可能与真实的半影函数有偏差；但主导观感的两个特征——半影宽度随遮挡距离变化、接触处锐利——是对的。这也是今天 UE 的级联阴影 / Virtual Shadow Map 仍然用固定 PCF 加抖动、而把真正的接触硬化交给距离场软阴影或光线追踪的原因之一：固定 PCF 简单可控，PCSS 则要把每光源每像素的采样数提到约 100 次。顺带一提，第 1 页那张无图注的渲染图选得很聪明：大量相互接触的餐具 + 高频纹理地面，同时展示接触硬化与采样噪声，等于一张图给出正反两面的证据。

英文原文
This sketch presents a new method, called Percentage-Closer Soft Shadows (PCSS), for generating perceptually accurate soft shadows. Based on shadow mapping [Williams 1978] and percentage-closer filtering (PCF) [Reeves et al. 1987], PCSS has these key characteristics: | - Generates perceptually accurate soft shadows | - Uses a single light source sample (one shadow map) | - Requires no pre-processing, post-processing, or additional geometry | - Seamlessly replaces a traditional shadow map query (embodies the same advantages as traditional shadow mapping—independent of scene complexity, works with alpha testing, displacement mapping, and so on) | - Runs in real-time on current consumer graphics hardware | This combination makes it uniquely suitable for a wide range of applications, from next-generation games to DCC/CAD applications. Because it uses just a single sample and requires no special processing steps, the technique easily replaces existing shadow mapping shader code in an application while producing much more compelling images. The only required change is to replace the typical shadow mapping pixel shader with a PCSS shader.

这篇 short sketch 提出一种名为 PCSS（基于百分比渐近滤波的软阴影，Percentage-Closer Soft Shadows）的新方法，用于生成感知上准确的软阴影。PCSS 建立在阴影映射（shadow mapping）[Williams 1978] 与百分比渐近滤波（PCF，percentage-closer filtering）[Reeves et al. 1987] 之上，具有以下关键特性： | - 生成感知上准确的软阴影 | - 只使用单次光源采样（仅需一张 shadow map） | - 无需预处理、后处理或额外几何体 | - 可无缝替换传统的 shadow map 查询（具备传统阴影映射的全部优点——与场景复杂度无关，支持 alpha test、displacement mapping 等） | - 可在当时消费级图形硬件上实时运行 | 这些特性叠加起来，使它格外适合从次世代游戏到 DCC/CAD 应用的广泛场景。由于只使用单次采样、也不需要任何特殊处理步骤，这项技术可以轻易替换应用中现有的阴影映射 shader 代码，同时生成更具说服力的画面。唯一需要的改动，就是把典型的阴影映射像素 shader 换成 PCSS shader。

🔍 专家解析

这一段是全文的"接口声明"，逐条读都有工程含义。（1）"生成感知上准确的软阴影"：PCSS 给出的不是能量正确的面积光积分，而是半影宽度正确、接触处锐利的近似；视觉上主导软阴影真实感的正是这两点。（2）"单次光源采样（一张 shadow map）"：显存 footprint 与 shadow pass 成本不变，这使得它对已有管线是零侵入的。（3）"无需预处理/后处理/额外几何"：对比需要法线/几何缓冲的方案、需要挤出闭合壳的 shadow volume 类方案，PCSS 不新增 draw call，也不要求网格流形闭合——这对带大量 alpha test 植被、蒙皮角色、displacement 的真实场景是决定性优势，因为这些几何要么无法闭合、要么二次渲染代价高。（4）"无缝替换传统 shadow map 查询"：在 DX12/Vulkan 里就是比较采样器的一次对比查询，换成"blocker search + penumbra estimate + PCF 循环"，返回值语义仍是 [0,1] 的遮挡率，直接乘到光照项上。（5）"当时消费级硬件实时"：2005 年指 GeForce 6/7 一类 SM2/SM3 设备，它们已有硬件 PCF（对比较结果做双线性插值），这为第三步提供了硬件支撑。最后一句"唯一需要的改动是换掉像素 shader"在今天的引擎里对应：不改 ShadowDepth pass、不改光空间矩阵与视锥（frustum）裁剪、不改 cascade 分配，只在着色的阴影采样函数里替换实现——这也是它至今仍被当作"最小改动软阴影"基准的原因。DCC/CAD 场景则看重它不需要任何离线烘焙。

2. Previous Work
🔍 编辑部按

相关工作一节的分量远超它的长度。作者把评价标准设为三条：ease of integration（易集成）、robustness（稳健性）、interactivity（交互性），并点名既有方法的通病——"umbras that do not shrink as penumbras grow"（本影不随半影变宽而收缩）。这句话是理解 PCSS 卖点的钥匙：物理上，半影越宽意味着光源的可见区域被摊得越开，本影必须相应收窄、最终趋于遮挡物的硬轮廓；而当年大量"把阴影模糊一下"的近似（对 shadow map 做固定半径模糊、penumbra map 类技巧、固定抖动采样）会同时把本影也糊掉，导致接触处依然发虚，看起来像失焦而不是像面光源阴影。Hasenfratz 2003 的综述至今仍是实时软阴影算法分类学的标准入口，把方法按"基于 shadow volume""基于 shadow map""基于光线跟踪/求解器"分族，读它能快速定位 PCSS 在谱系中的位置：它属于 shadow map 族、非卷积（保留原始深度比较）分支，靠自适应滤波半径获得软度。

英文原文
The history of shadow generation in computer graphics is vast and rich. A good survey of shadowing techniques can be found in [Hasenfratz 2003]. While many attempts to generate soft shadows exist, none produce results as realistic as ours with the same features: ease of integration, robustness, and interactivity. Common failings include producing umbras that do not shrink as penumbras grow.

计算机图形学中阴影生成的历史浩瀚而丰富。文献 [Hasenfratz 2003] 是一份很好的阴影技术综述。尽管生成软阴影的尝试很多，但没有一种能在同样具备易集成、稳健性与交互性的前提下，产生像我们这样真实的结果。常见的缺陷包括：本影不随半影变宽而收缩。

🔍 专家解析

展开"本影不收缩"为什么是常见病。面光源下的真实阴影由三区构成：本影（umbra，光源完全不可见）、半影（penumbra，光源部分可见）、被照亮区。半影宽度正比于遮挡物到接收体的距离，本影宽度则反比于该距离——接收体贴近遮挡物时，本影趋向遮挡物的硬轮廓；远离时本影收缩、半影扩张。任何把"软"实现为"固定模糊半径"或"固定采样抖动"的方法，都会让半影与本影一起变宽，接触处不硬，物件的"着地感"随之消失，这正是静态截图里最容易看出破绽的指标。按 Hasenfratz 2003 的分类，当年的主要路线有：软阴影体（soft shadow volumes，如 Chan & Durand 2004 及后续工作，需要挤出几何、代价高且难处理 alpha）、多重光源采样与多重 shadow map（成本随样本线性增长）、以及基于滤波/卷积的 shadow map——Variance Shadow Maps 要到 2006 年才发表（本文写作时尚未出现），同类还有后来的 Convolution Shadow Maps、Exponential VSM、Moment Shadow Maps（Peters & Klein 2015）。滤波类方法用可卷积的深度表示换取"一次模糊就得到任意宽度的软阴影"，代价是 light bleeding、曲率/分辨率伪影与精度问题；PCSS 则保留不可卷积的原始深度比较，用"自适应滤波半径"换软度，两者是互补的取舍——这也解释了为什么后来的实现常把二者混用，例如用 min-max 层级或 VSM 式的结构来加速 PCSS 的遮挡物搜索，而半影内的最终积分仍交给 PCF 或少量光线。PCSS 把"本影收缩"这件事变成公式的自然结果：当接收体深度等于遮挡物深度时半影宽度归零，剩下的正是硬本影轮廓。

3. PCSS（基于百分比渐近滤波的软阴影）

3. Percentage-Closer Soft Shadows
🔍 编辑部按

第三节是全文的技术核心，只有两段正文加三步流程。关键语义变化在第一句：PCSS 在每个眼视（eye view）像素上返回一个浮点值，表示该点的遮挡量（0 = 全亮，1 = 全影，中间为半影），替代普通阴影映射里的单次深度比较（返回 0/1）。也就是说 PCSS 的输出类型与传统阴影映射兼容——都是"一个乘到光照上的标量"，所以它能嵌进任何现有着色模型，包括延迟/分簇前向的阴影数组。三步结构（blocker search → penumbra estimation → filtering）是本文最大的贡献：它把"软阴影"分解为"估计局部平均遮挡深度"与"按估计宽度做 PCF"两个子问题，前者是统计、后者是标准硬件能力。今天各引擎里的接触硬化阴影滤波，无论叫什么名字，几乎都保持这三步骨架；差别只在采样分布、层级加速与是否用时间滤波收尾。

🔍 专家解析

"PCF 核越大阴影越软"这一观察，其实是百分比渐近滤波（PCF）的副产品。Reeves 1987 的 PCF 本意是抗锯齿：对深度贴图上一个小邻域做多次深度比较再平均，把 0/1 的硬边变成渐变。固定小核（如 3×3）的 PCF 只能给出略微发灰的硬边——因为滤波宽度固定，阴影边缘的过渡带在世界空间里是恒定宽度，与遮挡物离接收体多远完全无关，所以它"抗锯齿但仍然硬"；把核拉大能得到软边，但全场景统一变软，接触处也跟着糊，这正是上一节批评的"本影不收缩"。PCSS 的洞察是：滤波半径不该是常量，而应等于该像素处的半影宽度，于是问题转化为"逐像素估计半影宽度"。注意这一步是逐像素、逐光源的，无法预先烘焙进 shadow map，必须在接收体着色时现场计算，这也是 PCSS 成本的来源：每个像素要多跑两段采样循环（搜索与最终滤波）。工程上还有一点常被忽略：半影估计用的深度必须是光空间（light space）线性深度。透视光源的非线性设备深度在近处被严重压缩，若直接拿来相减，(d_Receiver − d_Blocker) 会失真、半影宽度算错；DX12/Vulkan 下通常在 shadow pass 里另存一张线性深度 R16F 目标，或在着色时用 DeviceZ 反投影回 view-space Z。此外，"replacing the traditional depth comparison"也提醒我们：普通阴影映射里那次比较并没有消失，它被搬进了第一步（判定哪些 texel 是遮挡物）与第三步（PCF 的每一次比较）里。

英文原文
Step 1: Blocker search. We search the shadow map and average the depths that are closer to the light source than to the point being shaded (the "receiver"). The size of the search region depends on the light size and the receiver's distance from the light source. | Step 2: Penumbra estimation. Using a parallel planes approximation, we estimate the penumbra width based on the light size and blocker/receiver distances from the light: w_Penumbra = (d_Receiver - d_Blocker) * w_Light / d_Blocker | Step 3: Filtering. Now we perform a typical PCF step on the shadow map using a kernel size proportional to the penumbra estimate from Step 2.

步骤 1：遮挡物（blocker）搜索。我们在 shadow map 上搜索，并把那些比被着色点（即"接收体（receiver）"）更靠近光源的深度取平均。搜索区域的大小取决于光源尺寸以及接收体到光源的距离。 | 步骤 2：半影估计。利用平行平面近似，我们基于光源尺寸以及遮挡物/接收体到光源的距离来估计半影宽度：w_Penumbra = (d_Receiver - d_Blocker) * w_Light / d_Blocker | 步骤 3：滤波。现在我们在 shadow map 上执行一次典型的 PCF，其核尺寸与步骤 2 得到的半影估计成正比。

🔍 专家解析

三步逐一拆解。【步骤 1（遮挡物搜索）】在 shadow map 上以被着色点为中心取一个邻域，把所有深度小于（更靠近光源）该点深度 d_Receiver 的 texel 视为遮挡物，对它们的深度求平均得到 d_Blocker。三个要点：(1) 搜索半径不是常量——它等于光源在该点处的投影足迹，标准实现按 shadow map UV 计为 searchRadius_uv ≈ w_Light / d_Receiver（比例系数视光源张角/正交归一化而定），因为从被着色点看向光源，光源张成的锥在深度贴图上的落点范围就是这样；(2) 判据实为 depth < d_Receiver − 偏移（bias），与普通阴影映射里对抗阴影痤疮（shadow acne）的 slope-scaled bias 是同一个量；bias 过大时紧贴接收体的遮挡物会被漏掉，接触硬化失效；(3) 若邻域内没有比 d_Receiver 更近的 texel，说明该点全亮，直接返回 1 跳过后面两步——这是最常见的早退分支，也是 PCSS 在大部分受光像素上并不比普通 PCF 贵的原因。用平均深度代表整个遮挡分布，等价于"平行平面、单一遮挡板"假设（即补充材料第 3 页的假设）：对同一深度上的一块遮挡板它是精确的；对前景细杆 + 后景墙面这类多深度混合，平均值落在两者之间，半影估计有偏差，但通常仍远好于固定半径。【步骤 2（半影估计）】w_Penumbra = (d_Receiver − d_Blocker) · w_Light / d_Blocker，即 dPenumbra = (d_receiver − d_blocker)·w_light / d_blocker。这是纯相似三角形：光源宽 w_Light，距光源 d_Blocker 处放遮挡板，接收体在 d_Receiver；光源边缘发出的光线越过遮挡板边缘后，在剩余距离 (d_Receiver − d_Blocker) 上继续张开，张开比例等于 (d_Receiver − d_Blocker)/d_Blocker，故接收体上半影半宽 = (w_Light/2)·(d_Receiver − d_Blocker)/d_Blocker。读出三个定性结论：接收体与遮挡物重合（d_Receiver = d_Blocker）时半影为 0 → 接触硬化；遮挡物越靠近光源（d_Blocker 小）半影越宽 → 高处/远处投射物的影子大片发虚；w_Light 越大越软。公式与第 3 页图中标注的 w_Light、d_Blocker、d_Receiver、w_Penumbra 一一对应。【步骤 3（滤波）】以与 w_Penumbra 成正比的核做标准 PCF。世界空间的半影宽要再除以 d_Receiver 换算成 shadow map UV（filterRadius_uv = w_Light·(d_Receiver − d_Blocker)/(d_Blocker·d_Receiver)），并与一个最小滤波半径取 max，避免本影边缘退化成 1-texel 硬边造成锯齿。成本与噪声：作者用 36 次搜索 + 64 次 PCF = 每像素每光源约 100 次深度采样。固定采样数下，大半影区每个样本覆盖的 texel 间隔很大，会产生条带与闪烁，惯用手段是泊松盘分布 + 逐像素随机旋转（interleaved gradient noise、blue-noise tile），把结构性条带打散成高频颗粒，再交给 TAA/时间滤波抹平——现代实现几乎都默认叠加 TAA。DX12/Vulkan 上的常见优化：遮挡搜索用 GatherCmp 一次取 4 个比较结果；PCF 循环用 SampleCmp 的硬件双线性比较（自 GeForce 6/7 起就存在）；并用 shadow map 的 mip / min-max 层级提前剔除无遮挡区域。

4. Results

结果一节的数字要放回 2005 年的语境里读：GeForce 7800 GTX（G70）是当时的旗舰，640×480 分辨率、约 75 fps、每像素 100 次深度采样（36 次搜索 + 64 次 PCF），说明 PCSS 在 SM3 时代的算力与纹理带宽下已经可以实时。作者强调这是 "relatively unoptimized" 的版本，等于声明还有可观优化空间——后来确实被逐步吃掉：更少样本、GatherCmp 合并取数、层级化搜索、半分辨率阴影等。另一句重要的话是"样本数可按光源大小与目标质量调整"：光源越小半影越窄，所需样本越少，算法自动退化回近似普通 PCF，这是 PCSS 在工程上"不会比现状差太多"的安全性质，也让它适合作为可扩展的质量档位（低/中/高 = 采样数与搜索上限的组合）。

🔍 专家解析

用现代视角读这段数字：每像素每光源约 100 次深度采样在今天依然是可观开销，只是相对算力便宜了一个数量级。实践中的取舍是——主光源（太阳、主聚光）用完整 PCSS；次要光源降低采样数（例如 8–16 次搜索 + 16–32 次 PCF）或直接退回固定 PCF；再配合半分辨率 shadow pass 加全分辨率重建、以及 TAA。若场景光源很多（延迟/分簇前向），通常把 PCSS 限制在最近或最重要的 N 个光源上。作者特别提到"带纹理场景效果尤其好"，这句话其实是噪声方面的坦白：固定采样数在大半影区会产生颗粒与条带，高频纹理既能掩盖这些瑕疵，也让软影边界更可读；而纯净的墙面/地面会把噪声暴露出来，所以现代实现几乎必须叠加随机旋转采样核 + TAA。后续加速路线值得记几条：用 min/max mip 或 summed-area 结构在搜索里跳过空区域；把第三步的 PCF 换成 VSM/EVSM/MSM 等可卷积表示，用一次硬件模糊代替 64 次采样（代价是 light bleeding 与矩精度问题）；以及在 UE 的 Virtual Shadow Map 这类 tile 化结构上，把 PCSS 的搜索半径映射到页选择与 LOD。采样噪声方面，固定样本 + 随机旋转的颗粒在现代管线里基本等同于"要不要 TAA"的问题——这也是 PCSS 的普及与 TAA 的普及几乎同步的原因。

🔍 专家解析

这段话给出了步骤 1 的精确语义：在 shadow map 的一块区域内，只把"深度比接收点更靠近光源"的深度值计入平均。三个实现要点值得展开。其一，判据是 depth < d_Receiver − bias，这个偏移（bias）与普通阴影映射里对抗阴影痤疮（shadow acne）的量是同一个，通常用 slope-scaled bias；若 bias 过大，紧贴接收体的遮挡物会被漏掉，接触硬化失效，物件会"悬浮"；若 bias 过小，接收体自身 texel 混入平均，会把 d_Blocker 拉向 d_Receiver，半影估计趋近 0，阴影整体变硬。其二，平均只对"判定为遮挡"的样本做，分母应是命中数而非采样总数，否则未命中样本（深度很远，常见清空值 1.0）会把 d_Blocker 拉向远处、半影被低估；命中数为 0 时提前退出、返回全亮，这条早退分支在多数受光像素上都能省掉后面两步。其三，求平均深度而非最近深度是刻意的设计：用最近遮挡深度会让估计对离群值极其敏感——一个离光源很近的细小遮挡物会把 d_Blocker 拉到极小，半影被放大到荒谬；平均是一个稳健统计，代价是多个不同深度的遮挡物混合时结果有偏差（平均值落在真实遮挡板之间的某个位置）。实践中常见的改进是把 blocker search 的结果与深度直方图/分层平均结合，或按深度加权，以缓解多遮挡物混叠时的误差。

第二张图把抽象几何落到了实现层面：黄色为光源，灰色平面是 Shadow Map（光源视锥中的深度贴图），蓝色立方体是场景中的遮挡物，深蓝色平面是场景与接收体。红色区域在 shadow map 上，正是被着色点（红色虚线的汇聚点）按光源尺寸投影出来的搜索窗口；红色虚线表示从被着色点出发、穿过 shadow map 各 texel 射向光源的采样线。读图要点有三。第一，搜索窗口的大小由光源尺寸与被着色点深度共同决定，这就是正文 "The size of the search region depends on the light size and the receiver's distance from the light source" 的几何解释——光源越大、被着色点离光源越近，窗口越大。第二，窗口内每个 texel 存的是"当前离光源最近的深度"，与 d_Receiver 比较即可判定该 texel 是否为遮挡物；这意味着搜索窗口必须足够大，大到能覆盖所有可能遮挡该点的遮挡物的投影，否则会漏掉真实的遮挡物、把半影算小（漏遮挡的错误表现为阴影过窄过硬，且随视角漂移）。第三，窗口是矩形而实际需要的可能是圆形/椭圆形，实现里通常用旋转后的泊松盘采样填进正方形窗口，或在各向异性光源（拉长的矩形光）下用椭圆核。这张图也说明了 PCSS 与普通 PCF 的唯一结构差别：PCF 的窗口大小由人为指定，PCSS 的窗口大小由几何推导得出。

半影尺寸估计步骤

Penumbra Size Estimation Step
🔍 编辑部按

第 3 页补充材料是全文唯一给出完整公式形态的地方，也是被后续论文、教材与引擎文档引用最多的图。它把步骤 2 的"平行平面近似"（parallel planes approximation）画成相似三角形：假设光源、遮挡物、接收体三者互相平行，半影宽度便可由纯比例关系得出，不需要任何积分。作者在正文里说这个假设 works very well in practice and could be relaxed as an improvement——放松它意味着按遮挡物/接收体的真实朝向计算投影，例如用遮挡物法线与光线方向修正有效光源宽度，或对接收体斜面按 cos 因子缩放半影、把"宽度"升级为带方向的"各向异性半影"。实际引擎里很少这么做：一来误差在视觉上不占主导（半影内的亮度本身由 PCF 采样分布决定，已经不精确），二来斜面接受的光照已被 N·L 项衰减，半影宽度的朝向误差被掩盖。理解这张图最好的方式是自己推一遍相似三角形，然后把三个定性结论背下来：接触即硬化、遮挡物越远半影越窄、光源越大半影越宽。

英文原文
The following diagram illustrates the geometry for estimating the penumbra size, assuming that the blocker, receiver, and light source are parallel. This assumption works very well in practice and could be relaxed as an improvement.

下图展示了估计半影尺寸所用的几何关系，其中假设遮挡物、接收体与光源相互平行。这一假设在实践中效果非常好，作为一种改进也可以将其放松。

🔍 专家解析

这段正文有三个信息点。第一，假设的对象是"blocker、receiver、light source 三者平行"，即把复杂的三维遮挡关系压缩成一个一维宽度问题，这正是它能只用一次除法就完成估计的原因——也正因为如此，半影估计几乎不花算力，真正的开销在第一步与第三步的采样循环上。第二，"works very well in practice"是经验判断而非理论结论：接触硬化与人眼对半影宽度的感知，主要由"遮挡物离接收体多远"决定，平行假设在这一点上是定性正确的，其余的朝向误差并不敏感。第三，"could be relaxed as an improvement"留下的改进空间，后续工作确实做过：按各向异性的光源投影把半影从"宽度"升级为"方向性椭圆半影"；在遮挡搜索时顺带估计遮挡深度的分布（而不只是平均值），以处理多遮挡物混叠；以及把半影估计与屏幕空间/光空间的层级结构结合，实现与距离自适应的滤波。这些改进都没有改变三步法的骨架，只是把每一步的统计量做得更准。另一个值得记住的实践细节：半影估计假设的是"存在遮挡"，因此它必须发生在遮挡搜索确认命中之后；在没有遮挡物时套用公式会得到无意义的负值或发散值（见下一块的边界条件讨论）。

英文原文
[Uncaptioned diagram plus equation, page 3: at the top a yellow light bar labelled w_Light, with an orange span A; d_Blocker measures the vertical distance from the light down to a green bar labelled "Blocker"; d_Receiver measures the distance from the light down to a blue bar labelled "Receiver"; at the bottom an orange span B and a grey bracket labelled w_Penumbra mark the penumbra extent on the receiver; yellow dashed lines show the extreme light rays grazing the blocker edge. To the right: w_Penumbra = ((d_Receiver - d_Blocker) * w_Light) / d_Blocker, with the note "Assumes that blocker, receiver, and light are parallel".]

[第 3 页图与公式，原图无图注，此为编者按图补写：顶部黄色光条标注 w_Light（光源宽度），旁边有橙色跨度 A；d_Blocker 标注从光源到绿色"Blocker"（遮挡物）的垂直距离；d_Receiver 标注从光源到蓝色"Receiver"（接收体）的距离；底部橙色跨度 B 与灰色花括号 w_Penumbra 标出接收体上半影的范围；黄绿色虚线表示掠过遮挡物边缘的极端光线。右侧公式：w_Penumbra = ((d_Receiver - d_Blocker) * w_Light) / d_Blocker，图下附注"Assumes that blocker, receiver, and light are parallel"（假设遮挡物、接收体与光源相互平行）。]

🔍 专家解析

原文公式提取损坏，按标准形式重建：w_Penumbra = ((d_Receiver − d_Blocker) · w_Light) / d_Blocker，与页面渲染图及第 1 页正文行内公式一致。推导（相似三角形）：设光源半宽为 w_Light/2，遮挡板边缘水平位置为 x_b，深度为 d_Blocker；从光源边缘 (x_l, 0) 过遮挡板边缘 (x_b, d_Blocker) 的直线在深度 d 处的水平位置为 x(d) = x_l + (d/d_Blocker)(x_b − x_l)。令 d = d_Receiver 得半影外缘；再减去遮挡板边缘在接收体深度上的投影 x_b·(d_Receiver/d_Blocker)，化简后得半影半宽 = (w_Light/2)·(d_Receiver − d_Blocker)/d_Blocker，乘 2 即上式（图中 A、B 正是这两段水平跨度）。工程换算与边界条件：(1) 三个深度必须同为光空间线性深度，w_Light 用世界单位，得到的 w_Penumbra 也是世界单位，做 PCF 时再除以 d_Receiver 换算成 shadow map UV，即 filterRadius_uv = w_Light·(d_Receiver − d_Blocker)/(d_Blocker·d_Receiver)；(2) d_Receiver = d_Blocker 时半影为 0，这正是接触硬化（contact hardening）——物件贴合处阴影锐利，离得越远越虚；(3) d_Blocker → 0（遮挡物贴近光源）时公式发散，实现必须 clamp（例如限制 d_Blocker ≥ 某个最小深度，或限制最大滤波半径）；(4) 遮挡搜索未命中时公式不适用，应直接返回全亮；(5) 结果要与最小滤波宽度取 max，否则本影边缘会退化成 1-texel 硬边并出现锯齿；(6) 该公式只给出"宽度"，半影内的明暗剖面形状由第三步 PCF 的采样分布决定，因此 PCSS 不保证能量守恒——同样是 w_Penumbra 宽的半影，用 8 个样本和 64 个样本的灰度分布会不同。这也是它与真正的面光源卷积（Variance/Moment Shadow Maps、或光线追踪 + 降噪）之间的本质差距：PCSS 给对了几何尺度，没给对辐射分布。现代对照：UE 的 Directional Light "Source Angle"、Unity HDRP 的光源 radius/angle 把 w_Light 暴露为美术参数，但背后的滤波不一定是严格 PCSS；Ray Traced PCSS（RTXDI/ReSTIR 时代）则用真实阴影射线取得物理正确的半影，再交给 SVGF、ReLAX 等空时降噪器收敛，可视为本图的精确版本。

第 4 页用同一场景在三档光源尺寸下的截图，直观验证 w_Light 是算法唯一的"艺术参数"：光源越小，半影越窄、越接近硬阴影；光源越大，半影越宽、接触硬化越明显。三张图都选取了多个物体相互接触、堆叠的复杂遮挡，这正是最能暴露"本影不收缩"缺陷的场景，也是 PCSS 相对固定模糊最占优的场景。仔细看可以确认：遮挡物相互接触以及物件落地的地方阴影依然锐利，而位置越高（离接收体越远）的部分越虚——这就是接触硬化的直接视觉证据。截图窗口带有 "Frame: 0 / Perspective" 的叠加信息，属于当年 NVIDIA 示例程序（FX Composer / DirectX SDK 示例一类）的取景框，说明作者是在实时交互程序里截的图，而非离线渲染。作者在 Results 里说带纹理的场景效果尤其好，这里也能看出来：高频纹理地面既能掩盖固定采样数的颗粒噪声，又为软影边界提供了可读的参照物；如果是干净的墙面，同样的采样设置会更显噪。

🔍 专家解析

三行原文分别对应三张截图，逐张看差异最有启发。中等光源（Figure 4）：物体接触地面处是硬轮廓，向上逐渐展开成宽半影，是三张里最接近真实面光源观感的一张，也是 PCSS 的"设计工作点"。小光源（Figure 5）：半影宽度按公式随 w_Light 线性缩小，画面接近传统阴影映射的硬阴影——此时 36 + 64 次采样其实大部分是浪费，这正是正文"采样数可按光源尺寸调整"的适用场景：光源小就减样本，性能随之回收。大光源（Figure 6）：半影变得很宽，可以观察到固定采样数的局限——半影区内出现细微的采样颗粒/条带，需要靠随机旋转采样核、更高样本数或时间滤波来压制；同时滤波半径变大也意味着 shadow map 的有效分辨率被"摊薄"，过大的光源下细节会丢失，因此实现里通常给搜索/滤波半径设上限。从这张对比还能读出一条重要的工程规律：半影宽度与光源尺寸是线性关系，所以"光源尺寸"应当作为美术可调参数暴露（现代引擎如 UE 方向光的 Source Angle、Unity HDRP 的光源 radius/shape 都是这一语义的延续，只是其背后的滤波未必是严格的 PCSS）；而采样数、搜索半径上限、最小/最大滤波半径则是工程侧的质量旋钮。换句话说，这篇 4 页的 sketch 实际上定义了此后二十年引擎阴影参数面板的接口形状——美术调光源大小，引擎调采样与滤波，两者通过 dPenumbra = (d_receiver − d_blocker)·w_light / d_blocker 这条公式解耦。
